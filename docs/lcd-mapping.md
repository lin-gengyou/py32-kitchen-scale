# HT1621B 与本板段码映射

## 控制接口

| HT1621B | 主控 | 主板网络 |
|---|---|---|
| CS# | PB2 | LCD_CS |
| WR# | PA5 | TFT_SCL，共享总线 |
| DATA | PA7 | TFT_SDA，共享总线 |
| RD# | PF1 | LCD_RD，写模式保持高 |
| TFT片选 | PA4 | TFT_CS，段码驱动期间保持高 |

初始化使用内部256kHz RC、1/3偏置、4COM、系统使能及LCD使能。命令为100前缀加9位，RAM写为101前缀、6位地址、D0～D3。软件只发送改变的RAM单元，待机发送LCD_OFF和SYS_DIS。

## 本板地址与公开玻璃表的转换

源码 `src/lcd_ht1621.c` 的 `digit()` 集中定义映射。地址指HT1621的0～31号RAM单元，位0～3指COM0～3。

| 逻辑数字 | 两个HT1621地址 | 两组段顺序（bit0至bit3） |
|---|---|---|
| 小字第1位 | 0 / 1 | D,E,G,F / DP,C,B,A |
| 小字第2位 | 2 / 3 | D,E,G,F / DP,C,B,A |
| 小字第3位 | 4 / 5 | D,E,G,F / DP,C,B,A |
| 小字第4位 | 6 / **7** | D,E,G,F / 冒号,C,B,A |
| 数值第1位（玻璃第5位） | **8 / 9** | F,G,E,D / A,B,C,DP |
| 数值第2位 | **10 / 11** | F,G,E,D / A,B,C,DP |
| 数值第3位 | **12 / 13** | F,G,E,D / A,B,C,DP |
| 数值第4位 | **16 / 17** | F,G,E,D / A,B,C,DP |
| 数值第5位 | **18 / 19** | F,G,E,D / A,B,C,DP |
| 数值第6位 | **20 / 21** | F,G,E,D / A,B,C,图标 |

这里必须使用主板网络号，不能把公开资料里的玻璃SEG序号直接作为HT1621地址。例如U9的16脚接主板SEG8，因此数值区从地址8开始；旧版把第四个小字位第二组段套为地址22；2026-11-12实机只增加地址7的B/C段后，用户确认数字4完整，因此驱动以实机验证的地址7为准。原图脚位标注与当前实物的一致性需另行核对。数字布局和厂商公开的段名称表分开处理。

v1.1.1菜单改为01～15数字编号；参数页短字母仍为七段近似形状。重量用整数mg计算后转成g一位小数或kg四位小数，不使用浮点格式化。

## 本机显示反馈与固定缺段

2026-11-11，用户在实际板子上反馈：初次显示位置错位；修正上述PCB地址后，文字和位置基本对应。

全段自检仍有一处固定现象：**中间一排第三个数字显示7，其余绝大多数为8**。全段自检会将32个RAM单元全部写为0xF，不经过字符字模，2026-11-12新增从HT1621本体读取RAM的诊断，实测32项均读回0xF、比较差异为0，用户确认此位仍为7。故障范围在显示RAM之后的段输出通道。

按当前映射，该数字的F/G/E/D四段共用 **SEG12**：检查路径为 **U10 HT1621B的44脚 → SEG12网络 → U9玻璃的20脚**。这一组都不亮而A/B/C仍亮，就会使全亮数字看起来像7。焊接、连线或玻璃引脚接触属于该通道的具体检查位置；当前已取得HT1621内部RAM读回和用户屏幕反馈，尚未测量SEG12引脚波形或导通，因此焊点、走线、控制器输出级和玻璃之间仍需电气区分。称重前应先恢复这一固定段线，避免数字被误读。

## v1.1.1实物诊断

- 上方第四位4：原表用了SEG6/22；在相同图案下仅增加SEG7=0x6，用户确认4恢复完整；已固定为SEG6/7。
- 数字图案：实际读回HT1621的32项RAM与发送帧完全一致，SEG12读回0xA，对应本次数字3所需的中横G和底横D。
- 全段图案：实际读回全部32项为0xF，比较差异为0；用户确认其余基本为8，第三位仍为7。它没有恢复D/E/F/G这组段。
- 本机自检编号13的第四页显示1304与0/1/2，表示上一幅图案的控制器RAM一致/不一致/尚未检查。
